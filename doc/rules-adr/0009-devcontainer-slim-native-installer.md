# 0009. devcontainer は slim イメージ＋vscode ユーザー＋ネイティブインストーラにする

- 状態：承認
- 日付：2026-10-21
- 関連：rules 9 章

## 背景

案件ごとに devcontainer を書いている。容量は抑えたいが、削減に工数をかけたくない。

## 決定

- ベースは言語の公式 slim イメージにする。なければ `debian:trixie-slim`。
- ユーザーは `vscode` にする。
- Claude Code はネイティブインストーラで入れる（Node.js は不要）。
- ログイン状態は、名前付きボリューム（`~/.claude`）と `CLAUDE_CONFIG_DIR` で、作り直しても残す。
- 容量の削減は 3 つだけにする：`--no-install-recommends`・apt のキャッシュ削除・`RUN` をまとめる。
- 通信制限（ファイアウォール）は雛形に入れない。制限する案件では `code.claude.com` を許可に含める。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| `mcr.microsoft.com/devcontainers/base` | 数百 MB あり、容量削減の方針に合わない |
| 常に `debian:trixie-slim` に言語を足す | 言語の導入を毎回自分で書くことになる |
| Alpine | musl 由来の不具合で時間を取られやすい |
| 多段ビルドなどの本格的な削減 | 工数に見合わない |
| Claude Code の Dev Container Feature や npm で入れる | Node.js が必要になり、容量が増える |
| 公式の参考例のファイアウォールを入れる | 追加の権限（NET_ADMIN）が要り、工数がかかる |

## 結果

- 良くなること：小さめのイメージで、言語の道具の入れ直しが要らない。
- 引き受けること：
  - 一般ユーザーの作成を自分で書く。
  - sudo を入れないため、道具を足すときは Dockerfile を直して作り直す。
  - 通信は制限されない。
