# 0017. ブランチ名は切る前に提案し、了承を得る

- 状態：承認
- 日付：2026-10-21
- 関連：rules 2 章・3 章・[0015](0015-keep-the-process-light.md)

## 背景

rules 3 章は、ブランチ名を `<エージェント名>/<内容が分かる英語>` とし、セッションに割り当てられた名前は使わないと決めている。

ところが claude.ai のクラウドセッションでは、環境がセッションを作るときに `claude/<形容詞>-<人名など>-<英数字 6 文字>`（例：`claude/wizardly-darwin-sa9bms`）を割り当てる。2026-10-21 に 2 つのセッションで確かめたところ、指示なしで始めても、別の環境で依頼文から始めても、名前は内容と関係なかった。さらに環境は「許可なく別のブランチに push しない」とエージェントに指示する。

リポの規則を読んだエージェントも、明示的な許可がないとして割り当ての名前に留まった。規則を書くだけでは、内容が分かる名前にならない。

## 決定

- ブランチを切る前に、エージェントが名前を提案し、ユーザーの了承を得る。この了承を、別の名前への push の許可とする。
- 提案は相談の「決めてほしいこと」に含め、確認を増やさない（[0015](0015-keep-the-process-light.md)）。仕様書の下書きもブランチにコミットするので、仕様書より前に決める。相談を経ない依頼では、最初の返事で聞く。
- 依頼文で名前が指定されていれば、提案は要らない。
- 了承がないうちは、割り当ての名前で進めず、止まって聞く。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| `CLAUDE.md` に「この規則を明示的な許可とみなす」と書く | 規則を読んだエージェントが、それでも許可がないと判断した |
| エージェントが自分で名前を決めて push する | 環境の「許可なく別のブランチに push しない」に反する |
| ユーザーが依頼文に毎回名前を書く | 手間が増え、忘れやすい。決定の 3 つ目の項目として残す |
| 割り当ての名前を使ってよいことにする | PR やブランチの一覧から内容が分からない |
| 仕様書の承認と一緒に了承を得る | 仕様書の下書きをコミットするブランチが、その前に要る |

## 結果

- 良くなること：ブランチ名から内容が分かる。環境の指示と規則がぶつからない。
- 引き受けること：相談の「決めてほしいこと」が 1 つ増える。依頼文だけで動く実行では、名前の指定がなければ止まる。
