# 0017. ブランチ名は作業前に提案し、了承を得る

- 状態：承認
- 日付：2026-10-21
- 関連：rules 3 章

## 背景

rules 3 章は、ブランチ名を `<エージェント名>/<内容が分かる英語>` とし、セッションに割り当てられた名前は使わないと決めている。

ところが claude.ai のクラウドセッションでは、環境がセッションを作るときに `claude/<形容詞>-<人名など>-<英数字 6 文字>`（例：`claude/wizardly-darwin-sa9bms`）を割り当てる。名前は依頼の内容と関係なく、環境を変えても、依頼文から始めても同じだった。さらに環境は「許可なく別のブランチに push しない」とエージェントに指示する。

リポの規則を読んだエージェントも、明示的な許可がないとして割り当ての名前に留まった。規則を書くだけでは、内容が分かる名前にならない。

## 決定

- 作業を始める前に、エージェントがブランチ名を提案し、ユーザーの了承を得てから切る。この了承を、別の名前への push の許可とする。
- 提案は仕様書の確認と一緒に行い、やりとりを増やさない。文書だけの変更（仕様書なし）は、最初の返事で提案する。
- 依頼文で名前が指定されていれば、提案は要らない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| `CLAUDE.md` に「この規則を明示的な許可とみなす」と書く | 規則を読んだエージェントが、それでも許可がないと判断した |
| ユーザーが依頼文に毎回名前を書く | 手間が増え、忘れやすい。決定の 3 つ目の項目として残す |
| 割り当ての名前を使ってよいことにする | PR やブランチの一覧から内容が分からない |

## 結果

- 良くなること：ブランチ名から内容が分かる。環境の指示と規則がぶつからない。
- 引き受けること：ユーザーが名前を了承する手間が少し増える。
