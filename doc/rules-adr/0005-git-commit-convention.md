# 0005. コミットは Git 本来の慣習で書く

- 状態：承認
- 日付：2026-10-21
- 関連：rules 1 章・3 章

## 背景

コミットメッセージの形式を決めていなかったため、案件ごとにぶれていた。コミットを書くのはほぼ Claude なので、手間よりも、決まりがぶれないことのほうが重要になる。

## 決定

- コミットは英語で書く。
- 件名は命令形の動詞から始める（`Add …`・`Fix …`・`Update …`・`Remove …`・`Refactor …`）。50 文字程度にする。
- 理由（Why）は、空行の後の本文に書く。本文は 72 文字で折り返す。
- コードコメントは日本語、文書と PR 本文も日本語。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| Conventional Commits（`feat:` / `fix:`） | 強みは版の自動上げと CHANGELOG の自動生成だが、版は日付で（[0004](0004-calver-yyyy-m-n.md)）CHANGELOG は手書きなので使わない。今までの `Add …` 形式を続けたい |
| Conventional Commits（範囲あり、`feat(net):`） | 範囲の語が案件ごとに違い、ぶれやすい |
| 部位プレフィックス（`net: …`） | 機能の追加か修正かが分からない |
| gitmoji | 入力しにくい。少数派 |
| コミットも日本語 | 履歴は英語の慣習に合わせる |

## 結果

- 良くなること：自然な英文で読みやすい。今までのリリース手順のコミット名（`Add the spec for …`・`Release …`）とそのまま揃う。
- 引き受けること：種類（機能か修正か）で機械的に絞り込みにくい。
