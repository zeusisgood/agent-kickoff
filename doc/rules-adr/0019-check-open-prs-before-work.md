# 0019. ブランチを切る前に開いた PR を確かめる

- 状態：承認
- 日付：2026-11-04
- 関連：rules 2 章・3 章・13 章・[0013](0013-downstream-rule-version-check.md)・[0015](0015-keep-the-process-light.md)・[0017](0017-propose-branch-name-before-work.md)

## 背景

rules 3 章では、PR を出したあとは見張らず、結果は「次の作業を始めるときに確かめる」としている。けれども、開いた PR が残っていたときにどうするかは決めていなかった。

開いた PR に気づかずに `main` から新しいブランチを切ると、先の PR が取り込まれたあとに rebase や衝突の解消が要る。同じファイルを触っていれば、なおさら手間がかかる。

## 決定

- ブランチを切る前に、そのたびに開いている PR を確かめる。対象は、エージェントが出したものに限らず全部とする。ブランチを切らない相談だけなら要らない。
- 1 件でもあれば、番号・題名・ブランチを並べ、次のどれにするかをユーザーに聞く。
  - 既存のブランチに積む（内容が近いとき。その PR にコミットを足すので、新しい PR は作らない）
  - Merge を待ってから、新しい `main` で切る
  - 別のブランチで並行する（あとで rebase が要ると承知のうえで）
- この問いはブランチ名の提案（[0017](0017-propose-branch-name-before-work.md)）と同じ返事にまとめ、確認の回数を増やさない（[0015](0015-keep-the-process-light.md)）。
- 確かめられないとき（GitHub に入れないなど）は、止めずに一言添えて進める。人がいない実行では確かめない。どちらも原本の版の確認（[0013](0013-downstream-rule-version-check.md)）と同じ扱い。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 同じファイルを触る PR だけを相談する | ブランチを切る時点では変えるファイルが決まっておらず、判断がぶれる |
| 開いた PR があるうちは新しい作業を始めない | 関係のない PR でも止まり、重すぎる |
| エージェントが出した PR だけを確かめる | ユーザーが手で出した PR ともぶつかる |
| 原本の版と同じく、セッションの最初の作業だけで確かめる | 版はめったに変わらないが、PR は同じセッションの中でも増える。一覧を見るだけなので、毎回でも軽い |
| 今のまま、ぶつかったら rebase する | 防げる手間を毎回払うことになる |

## 結果

- 良くなること：先の PR と気づかずにぶつかることがなくなり、rebase の手間が減る。
- 引き受けること：関係のない PR が開いていても、一度は聞かれる。
