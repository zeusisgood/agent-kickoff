# 0013. ルールに版を付け、作業を始めるときに原本の版を確かめる

- 状態：承認
- 日付：2026-10-21
- 関連：rules 13 章・[0002](0002-public-template-repo-no-skill.md)・[0004](0004-calver-yyyy-m-n.md)・[0012](0012-upstream-rules-from-projects.md)

## 背景

案件にコピーしたルールは、原本を更新しても自動では追従しない。取り込む手順は未決だった（[0002](0002-public-template-repo-no-skill.md) の未決事項）。古いルールのまま作業を続けると、原本で直した問題が案件で繰り返される。

## 決定

- ルールに版を付ける。ルール版は原本の版と同じで、形式は `YYYY.M.N`（[0004](0004-calver-yyyy-m-n.md)）。最初の版は `2026.10.0`。
  - 版は `doc/rules.md` の冒頭に書く。
  - 変更点は `doc/rules-changelog.md` に 1 項目 1 行で書く。
- エージェントは、セッションの最初の作業を始めるときに、原本の `doc/rules-changelog.md` を読み、案件の版と比べる。
  - 新しければ手を止め、差分の要約（変更履歴の項目と、関係する rules-adr の番号）を見せて、取り込むかを相談する。
  - 「後で」と言われたら、`doc/TODO.md` の「原本から取り込む」に版を控えて元の作業に戻り、同じセッションでは再び聞かない。
  - 原本を読めないときは止めずに一言添える。人がいない実行では確かめない。
- 取り込みは、案件内の通常の流れ（ブランチ → PR）で行う。
- 案件では、`doc/rules.md` と `doc/rules-adr/` を直接直さない。案件固有の決まりは `AGENTS.md` か `doc/adr/` に書く。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 頼まれたときだけ取り込む（版の確認なし） | 頼むのを忘れると古いまま |
| git の submodule や subtree で取り込む | 仕組みが重い。「案件内の版を正とする」と合わない |
| Actions で定期的に差分を確かめ、issue を立てる | 案件ごとに設定と保守が要る |
| 作業のたびに確かめる | 1 つのセッションで何度も止まる |
| 差分の全文を見せる | 長くて判断しにくい。変更履歴の要約で足りる |
| ルール版を原本の版と別に持つ | 原本の中身はほぼルールなので、分ける意味が薄い |

## 結果

- 良くなること：原本が新しくなったことに、作業の最初に気づける。何が変わったかが 1 行ずつ分かる。取り込むかどうかを案件ごとに選べる。
- 引き受けること：
  - セッションの最初に毎回、原本を読む通信が発生する。
  - 原本を変えるたびに、ルール版と変更履歴を直す必要がある。
  - 案件ごとに直しているファイル（`AGENTS.md`・`.devcontainer/` など）は、手で差分を反映する。
