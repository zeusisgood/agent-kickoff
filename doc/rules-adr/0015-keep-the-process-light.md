# 0015. 進め方を重くしすぎない

- 状態：承認
- 日付：2026-10-21
- 関連：rules 0 章・2 章・[0013](0013-downstream-rule-version-check.md)

## 背景

先行事例の GitHub Spec Kit には、次のような批判がある。

- Markdown が大量にできる。
- 小さな変更には重い。
- ウォーターフォールの再来になる。

agent-kickoff も、仕様書・tasks・ADR・図と文書が増え、rules は 200 行を超えてきた。同じ道をたどらないよう、歯止めを置く。

## 決定

- **文書だけの変更**（README・doc・コメントの修正）は、仕様書なしで進めてよい。それ以外（不具合の修正を含む）は、今までどおり仕様書を書く。
- `doc/rules.md` は 300 行までを目安にする。超えそうなら、足す前に削れるものを探すか、付録に移す。
- ADR は「迷ったら書かない」（[0001](0001-record-decisions-in-adr.md)）を守る。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 不具合の修正も仕様書なしにする | 直し方に選択肢があることが多く、確認の場として仕様書を残したい |
| 1 ファイル程度の小さな修正も仕様書なしにする | 「小さい」の線引きがぶれる |
| 行数の目安を 250 行にする | 今の分量ですぐ見直しが要る |
| 行数の目安を置かない | 歯止めが利かない |

## 結果

- 良くなること：文書の手直しが軽くなる。rules が膨らみ続けるのを防げる。
- 引き受けること：不具合の修正には、小さくても仕様書が要る。300 行に近づいたら、整理の手間がかかる。
