# 0012. 案件で生まれたルールは、相談して明示的に指示されたときだけ原本に PR を出す

- 状態：承認
- 日付：2026-10-21
- 関連：rules 13 章・[0013](0013-downstream-rule-version-check.md)

## 背景

案件を進める中で、どの案件にも使えそうなルールが出てくる。それを原本（agent-kickoff）に戻す流れがなかった。

一方で、エージェントが勝手に原本へ PR を出すのは避けたい。また、作業中の環境によっては、他のリポに PR を出せないこともある。

## 決定

- エージェントは、汎用的に使えそうなルールに気づいたら一言提案する。強制はしない。
- 案件では `doc/TODO.md` の「原本へ提案」に要約だけを控える。
- 相談のうえ、**ユーザーから明示的に指示されたときだけ**原本に PR を出す。Merge はユーザーが行う。
- PR を出せない環境では、`doc/upstream-prompt.md` の雛形でプロンプトを作って渡す。ユーザーがそれを、PR を出せる環境に持ち出す。
- 原本を直すときの注意（このリポは案件のテンプレートでもあるので、`AGENTS.md` などの雛形を自分への指示として読まない）は、`doc/upstream-prompt.md` に書く。
- 合流したら、元の案件でも下り（[0013](0013-downstream-rule-version-check.md)）で取り込む。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 気づいたらエージェントが自動で原本に PR を出す | 原本は全案件に影響する。人が決めるべき |
| 候補を案件の ADR として書く | 技術の決定ではないルールまで ADR になる |
| 候補を専用のファイル（`doc/upstream.md`）に書く | ファイルが増える。文案は相談の場で作るので、案件には要約で足りる |
| 持ち出し用プロンプトの雛形を置かない | 毎回の形がぶれ、抜けが出る |
| 原本を直すときの手順を `CONTRIBUTING.md` に書く | 原本を直す経路はプロンプトか明示の指示に限られるので、雛形に書けば足りる。案件にもコピーされてしまう |

## 結果

- 良くなること：案件で得た学びが原本に戻る。原本への変更は必ず人が決める。PR を出せない環境でも手が止まらない。
- 引き受けること：ユーザーが PR を出せる環境にプロンプトを持ち出す手間がある。
