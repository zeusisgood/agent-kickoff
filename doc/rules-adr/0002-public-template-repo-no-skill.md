# 0002. ルールは公開のテンプレートリポに置き、スキルは作らない

- 状態：承認
- 日付：2026-10-21
- 関連：[0003](0003-kickoff-files-made-in-chat.md)

## 背景

Claude Code 向けのキックオフ（仕様書・devcontainer・`CLAUDE.md`）のたびに共通ルールを決め直すのは手間がかかる。そこで、ルールを 1 か所にまとめ、毎回それを読ませたい。

## 決定

- ルール本文と雛形は、公開リポ `zeusisgood/claude-kickoff` に置く。このリポを GitHub のテンプレートに設定し、新しい案件は「Use this template」で作る。
- キックオフの手順は `KICKOFF.md` に書く。チャットでは毎回リポの URL から読む。
- スキルは作らない。メモリに「キックオフは `claude-kickoff` の `KICKOFF.md` に従う」の 1 行だけを置く。
- 個人的な設定（vi の使い方・カラーコードなど）はリポに含めない（[0010](0010-personal-prefs-outside-repo.md)）。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 非公開リポ | チャットから URL で読めず、毎回リポの追加か添付が必要になる。公開する案件にはルールがコピーされるので、原本だけ隠しても効果が薄い。整っていない状態を見せたくないという懸念はあったが、README に「整備中」と書いて公開する |
| ルールをメモリに全文置く | 容量に上限がある。Claude Code からは読めない |
| ルールをスキルに同梱する | 直すたびにスキルを作り直す必要がある。原本が 2 か所に分かれる |
| 手順だけの薄いスキル | 発動は確実になるが、メモリの 1 行で足りる程度の頻度 |
| Claude Code のプラグインとして配る | 仕様書と devcontainer はチャットで作ると決めたため、Claude Code 側の仕組みは不要になった（[0003](0003-kickoff-files-made-in-chat.md)） |
| claude.ai のプロジェクトの資料に置く | 履歴が残りにくい。Claude Code からは見えない |
| キックオフのたびに全ファイルをチャットで作る | 置くファイルが 10 個前後になる。テンプレートなら共通部分は最初から揃う |

## 結果

- 良くなること：ルールを直す場所が常に 1 か所になる。新しい案件では、共通ファイルが最初から揃う。
- 引き受けること：
  - 整っていないルールも公開される。
  - 案件にコピーしたルールは、原本を直しても自動では追従しない（案件内の版を正とする）。
  - 既存のリポにはテンプレートが使えないので、手でコピーする。
